3) API endpoints (backend repository confirmation)
- GET current profile: GET /api/auth/profile (protected; Authorization: Bearer <token>)
  - Response: { success: true, message, data: { user: { ... } } }
  - Example returned user fields used by the UI: full_name, phone, username

- Update profile: PUT /api/auth/profile (protected; Authorization: Bearer <token>)
  - Request body: JSON with any of the updatable fields.
  - Confirmed updatable fields in backend: full_name, phone, college, department, administrative_position, degree, gender, role, leave_balances
  - NOTE: The current backend implementation (controllers/authController.updateProfile) does NOT accept or handle a password change field. If the UI includes "كلمة المرور الجديدة" and should change the password, implement one of the following:
    1) Add password handling server-side in updateProfile: accept `password` (or `new_password`) in request body, bcrypt-hash it and save (ensure strong validation and require current password or confirm flow), OR
    2) Create a separate endpoint `PUT /api/auth/password` or `POST /api/auth/change-password` that requires the current password + new password and securely updates it.

- new_password (optional if implemented): if provided, min length 8, recommend mix of letters and numbers. Inline helper text is already "اتركها فارغة إذا كنت لا تريد تغيير كلمة المرور". If password update is implemented server-side, require entering current password or a confirmation field (for security).

- Show success toast or inline message after successful update: e.g. "تم حفظ التغييرات".

10) Test cases (basic)
- Happy path: user edits full name and phone, presses save -> server returns 200 -> UI shows success and updated fields.
